# 0.3.13 开发版：全局范围与半折悬停

此说明对应已安装并经用户体验确认的 0.3.13，不改变已经发布的 v0.3.12 Release。

## 使用

应用设置中新增「作用范围 → 全局启用」。默认关闭，沿用桌面和亮屏锁屏范围；开启后应用于其他应用的可捕获画面，包括系统设置与本应用自身。受保护画面不保证可镜像。

连续 3 秒的铰链角度最大值减最小值不超过 10°，进入悬停使用状态。渲染器在约 220 ms 内将投影倾角退回零，距离模糊随投影一起减少，最后接近正常画面时撤去覆盖。不是直接隐藏一个仍处于折叠形状的图层。

悬停时不会因小幅晃动重复启动。相对进入悬停时的角度移动超过 10°，用约 160 ms 恢复跟随。完全展开/合拢、息屏或离开允许范围会清除悬停计时。计时由服务持续推进，即使静止后传感器不再发送新事件也能触发。

仅视觉效果退出。真实铰链角度继续提供给切屏控制器，悬停本身不会触发切屏覆盖的释放/重新申请。全局开关同时决定自定义切屏角度的适用场景。模糊和切屏角度的「恢复默认」保留作用范围选择。

## 实现与验证

- FoldHoldGate 使用完整滑动窗口的最大摆幅；避免首尾角度相同的来回摆动被误判静止。
- FoldReturnMotion 按时间插值到无变形平面，支持动画中途反向恢复；不改变模糊算法与屏幕方向映射。
- 宿主版本递增，确保升级后 Shizuku 重建宿主并部署新渲染 DEX；控制 DEX 未改动。
- JVM 测试覆盖 3 秒阈值、10° 边界、往返摆动、无传感器新事件、再次移动、息屏/端点/无效角度、220 ms 退出与恢复中断连续性。
- 模型测试、构建与 lint 通过；APK 已安装，设备上渲染 DEX 校验一致。实机记录到 102° 悬停退出完成、继续合拢后恢复跟随；系统设置内的全局覆盖 allowed=true / alive=true。
- 用户在系统设置中验证悬停后平滑恢复、继续开合后重新出现，反馈“现在是我预期的”。全局开关已由用户打开。
- 同时修复 Shizuku 启动超时残留的无进程服务记录：等待超过 20 秒仍未连接时清理该记录再请求启动，避免只重复绑定失败记录。
